# **표준 컨벤션: 메타데이터 태깅 및 데이터 품질 구현 규약**

본 문서는 개발자가 코드를 작성할 때 **OpenMetadata**와 연동하기 위해 지켜야 할 구체적인 태깅 방법과 품질 테스트 정의 규약을 정의합니다.

## **1\. 메타데이터 태깅 (Tagging & Classification)**

데이터 자산의 성격과 보안 수준을 명시하기 위해 다음 태그 체계를 준수합니다.

### **1.1. 보안 분류 (Classification: PII)**

개인정보가 포함된 컬럼은 반드시 PII(Personally Identifiable Information) 태그를 부착해야 합니다.

* **태그:** PII.Sensitive (전화번호, 주소), PII.NonSensitive (이름, 사번).  
* **적용 위치:** infrastructure/persistence/\*.schema.ts 파일의 컬럼 설명(Comment) 란.

### **1.2. 도메인 및 티어 분류 (Tiering)**

* **Tier 1 (Mission Critical):** 시스템 핵심 운영 데이터 (예: 배정 확정 데이터).  
* **Tier 2 (Operational):** 부가 정보, 로그 성격의 데이터.

## **2\. 데이터 품질 테스트 (Data Quality Test) 정의**

도메인 개발자는 자신이 설계한 테이블에 대해 최소 1개 이상의 **품질 테스트**를 정의해야 합니다.

### **2.1. 표준 테스트 유형**

1. **Column Null Count:** 필수 값이 비어있지 않은가?  
2. **Column Values To Be In Set:** 상태 값(Status)이 정의된 범위(PENDING, COMPLETED 등) 내에 있는가?  
3. **Table Row Count:** 데이터가 비정상적으로 급감하거나 급증하지 않았는가?  
4. **Custom SQL Test:** 비즈니스 복합 로직 검증 (예: 배정 완료 상태인데 담당자 ID가 없는 케이스 추출).

## **3\. 구현 가이드 (Example)**

### **3.1. DB 스키마 내 메타데이터 기술**

DB 스키마 정의 시 OpenMetadata가 읽어갈 수 있도록 상세한 설명을 추가합니다.

// infrastructure/persistence/assignment.schema.ts

export const assignments \= pgTable('assignments', {  
  id: uuid('id').primaryKey(),  
  // @Tag: PII.NonSensitive  
  // @Description: 배정된 담당자의 고유 식별자 (사번)  
  managerId: varchar('manager\_id', { length: 50 }).notNull(),  
    
  // @Tag: Tier.Tier1  
  // @Description: 배정의 현재 진행 상태 (PENDING, COMPLETED, CANCELED)  
  status: varchar('status', { length: 20 }).notNull(),  
    
  createdAt: timestamp('created\_at').defaultNow(),  
});

### **3.2. OpenMetadata API를 통한 품질 결과 전송 (Optional)**

애플리케이션 내의 검증 로직 결과나 배치 작업 결과를 직접 전송할 수 있습니다.

// application/services/quality-check.service.ts

async reportQuality(testResult: any) {  
  // OpenMetadata SDK를 사용하여 테스트 결과를 API Server로 전송  
  await this.openMetadataClient.postTestResult({  
    entityFQN: 'service.database.schema.table.column',  
    testCaseName: 'check\_null\_manager',  
    result: testResult.passed ? 'Success' : 'Failed',  
    timestamp: Date.now(),  
  });  
}

## **4\. 모니터링 및 알림 설정**

1. **OpenMetadata UI 접속:** 매일 아침 데이터 품질 대시보드를 확인합니다.  
2. **Slack 알림:** 품질 테스트 실패 시 \#data-ops-alerts 채널로 즉시 알림이 발송되도록 웹훅(Webhook)을 연결합니다.  
3. **Owner 책임:** 자신의 도메인에서 발생한 품질 오류는 해당 도메인 Owner(담당 개발자)가 당일 내로 원인을 파악하고 Task를 생성하여 처리합니다.
