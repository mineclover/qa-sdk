# **아키텍처 설계서: 데이터 거버넌스 및 메타데이터 관리 전략 (OpenMetadata)**

본 문서는 시스템 내 산재한 데이터 자산(DB, Kafka, Pipeline)을 중앙 집중적으로 관리하고, 데이터의 신뢰성과 투명성을 확보하기 위해 **OpenMetadata**를 연동하는 전략을 정의합니다.

## **1\. 아키텍처 통합 뷰 (Integration View)**

우리 시스템의 각 컴포넌트는 OpenMetadata 내에서 다음과 같은 **Service** 및 **Entity**로 매핑되어 관리됩니다.

### **1.1. 서비스(Service) 매핑**

* **Database Service:** Primary DB(Postgres/OCI), Read DB(Redis Stack).  
* **Messaging Service:** Kafka (Topics, Consumer Groups).  
* **Pipeline Service:** Ingestion 워커, Sync 워커(CDC 파이프라인).  
* **Application Service:** 도메인별 API 서버 (Metadata API를 통해 직접 정보 전달).

### **1.2. 계보(Lineage) 정의: 데이터의 흐름 시각화**

OpenMetadata를 통해 다음의 흐름을 자동으로 추적하고 시각화합니다.

1. **Write Path:** Primary DB Table \-\> Outbox Table \-\> Debezium Connector.  
2. **Event Path:** Debezium \-\> Kafka Topic \-\> Sync Worker(Consumer).  
3. **Read Path:** Sync Worker \-\> Read DB (JSON/Index).  
4. **Consumption:** Read DB \-\> Dashboard/API.

## **2\. 도메인 중심 거버넌스 (Domain-Driven Governance)**

우리의 \*\*Bounded Context(도메인 모듈)\*\*를 OpenMetadata의 조직 구조와 연동합니다.

* **Domain & Team:** \* src/modules/assignment \-\> OpenMetadata Domain: Assignment, Team: Assignment Team.  
  * 각 도메인 개발팀은 해당 도메인에 속한 Table, Topic, Pipeline의 **Owner**가 됩니다.  
* **Glossary (비즈니스 용어집):**  
  * 도메인 전문가와 협업하여 "배정(Assignment)", "공정(Process)" 등 핵심 용어를 정의하고, 이를 실제 DB 컬럼과 연결하여 개발자와 비즈니스팀 간의 언어 장벽을 해소합니다.

## **3\. 메타데이터 수집 전략 (Ingestion Strategy)**

### **3.1. 자동 수집 (Passive Ingestion)**

* OpenMetadata의 \*\*Ingestion Framework (Airflow 기반)\*\*를 사용하여 주기적으로 DB 스키마와 Kafka 토픽 리스트를 스캔합니다.  
* Drizzle/TypeORM 스키마 변경 시 자동으로 메타데이터가 업데이트되도록 파이프라인을 구성합니다.

### **3.2. 능동 주입 (Active Metadata Injection)**

* 애플리케이션 배포 시(CI/CD), Pulumi 코드가 실행된 후 \*\*OpenMetadata SDK(Python/Java)\*\*를 호출하여 최신 인프라 정보와 태그(PII 여부 등)를 즉시 업데이트합니다.  
* **코드 레벨 태깅:** DB 스키마 정의 파일(\*.schema.ts)에 주석이나 데코레이터 형태로 메타데이터 정보를 기술하고, 이를 파싱하여 OpenMetadata API로 전송합니다.

## **4\. 데이터 품질 및 관측성 (Observability)**

* **Data Quality Test:** \* Assignment 테이블의 담당자 ID가 NULL인 비율이 5%를 넘지 않는지 등 품질 테스트를 정의합니다.  
  * 테스트 실패 시 OpenMetadata API가 이를 감지하고 Slack 또는 이메일로 알림을 보냅니다.  
* **Profiler:**  
  * 주기적으로 데이터 분포를 분석하여, 특정 공정에 배정이 쏠리는 현상 등을 통계적으로 모니터링합니다.

## **5\. 기대 효과**

1. **데이터 발견(Discovery):** "담당자 배정 이력 데이터가 어디 있지?"라는 질문에 UI 검색 한 번으로 답할 수 있습니다.  
2. **영향도 분석:** 특정 테이블 구조 변경 시, 어떤 Kafka 토픽과 Read DB가 영향을 받는지 Lineage를 통해 사전에 파악합니다.  
3. **신뢰도 향상:** 데이터 품질 테스트 결과를 실시간으로 공유하여 데이터 기반 의사결정의 신뢰도를 높입니다.
