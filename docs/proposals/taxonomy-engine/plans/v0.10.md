# Taxonomy Engine v0.10 구현 계획 — Stage 3 Decision Sync

> **For agentic workers:** subagent-driven-development 또는 executing-plans 사용.

**Goal:** taxonomy-engine ↔ decision-flow 양방향 sync. yaml `lifecycle: tbd` + `decisionLink`가 markdown decision 파일과 자동 동기화.

**Architecture:** 신규 패키지 `taxonomy-decision-bridge` (taxonomy-engine과 decision-flow를 모두 의존). CLI `qa-sdk decision sync` 명령. Web `DecisionPanel`. decision 파일은 def-catalog 패턴(markdown + frontmatter).

**Tech Stack:** TypeScript ES2023, yaml@^2.8.3, vitest.

**Branch:** main 직진.

**Spec:** [`../concepts/decision-sync.md`](../concepts/decision-sync.md), [`../roadmap.md`](../roadmap.md) §Stage 3.

  id: string;

};

type DecisionFile = {

  body: string;             // 원본 markdown (재직렬화용)
};

## 결정 (구현 진입 전 정리)

- **bridge만 사용**: FlowEngine 직접 호출 안 함. FlowEngine의 schemas/instances/policies/gates 추상화는 lifecycle 단순 진행(tbd→review→approved)에 과함. 통합은 별도 작업.
- **`docs/decisions/`**: spec과 별도 카테고리 (decision은 흐름 기록, spec과 다른 layer). def-catalog scan 대상에 추가.
- **모두 commit**: evidence weight 변경도 매 commit — 운영 노이즈는 사용해보고 조정.
