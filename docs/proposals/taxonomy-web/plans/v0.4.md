# Taxonomy Web v0.4 구현 스펙 — Decision Demo Page

> taxonomy-decision-bridge v0.12~v0.14 기능(마커 확장/multi-gate/역방향 변환)을 브라우저에서 라이브 시연하는 데모 페이지.

**Goal:** markdown decision 파일을 입력 받아 마커 추출 → FlowSchema 변환 → multi-gate 의존성 그래프 + round-trip diff를 실시간으로 보여주는 데모 페이지를 taxonomy-web에 추가한다.

**Architecture:**
- `routes/DecisionDemoPage.tsx` — 라우트 entry. 텍스트 상태 + sample 전환 + `useDeferredValue`로 parse 부하 분산.
- `lib/decisionDemo.ts` / `lib/textDiff.ts` — React 미사용 순수 helper. 격리 테스트.
- `components/decision/` — 5개 단일 책임 컴포넌트 (cheatsheet/diff/graph/warning/error).
- `data/decisionDemoSamples.ts` — 3종 sample (skeleton / single-gate / multi-gate).
- 런타임 의존: `taxonomy-decision-bridge` (workspace). type-only: `decision-flow` (devDep).

**Base:** main (v0.12+v0.13+v0.14 commit 후).

순수 함수 4종:

| 함수 | 입력 | 출력 |
|---|---|---|
| `classifyParseError(message)` | parse 에러 메시지 | `{kind, message, hint}` — 4 카테고리 |
| `detectSkeleton(file, schema)` | DecisionFile + FlowSchema | `{isSkeleton, reason}` |

**판정 규칙:**

- **classifyParseError:** bridge의 throw 메시지 패턴 매칭 — `frontmatter 누락` / `frontmatter.lifecycle` / `frontmatter.<field>` / 그 외. 메시지가 바뀌면 함께 갱신 필요.
- **detectSkeleton:** 옵션 0건 + 증거 0건 → skeleton. multi-gate에서는 `file.markers.gates[].evidence` 합산.
- **analyzeEvidenceFanout:** multi-gate에서 같은 `requiredEvidence` kind를 여러 gate가 요구하면 round-trip 시 evidence 복제 위험 (from-flow-schema.ts:154-156, 187-191). 해당 kind와 gate 목록 반환.

**테스트 16건:** classify 4건, detectSkeleton 4건(샘플 3종 + 탐색단계), fanout 3건, cheatsheet 3건, sample 라운드트립 검증 2건.

### Task B2: `lib/textDiff.ts`

**Files:**
- Create: `packages/taxonomy-web/src/lib/textDiff.ts`
- Create: `packages/taxonomy-web/src/lib/textDiff.test.ts`

LCS 기반 line diff. round-trip 결과 시각화 외 비-목표.

```ts
export type DiffLine =
  | { kind: "same"; text; lineNoA; lineNoB }
  | { kind: "remove"; text; lineNoA }
  | { kind: "add"; text; lineNoB };

export function lineDiff(a: string, b: string): DiffLine[]
export function diffStats(diff): { added; removed; same }
```

- O(M*N) DP — round-trip markdown은 보통 < 200 line이라 충분.
- 테스트 6건: 동일/추가/제거/순서변경/빈입력/카운트.

## 의도된 제약

- **Round-trip evidence 손실:** multi-gate에서 evidence-kind 매칭이 N:M이면 `toMarkdown` 시 중복/누락 발생 가능. `EvidenceFanoutWarning`이 사용자에게 명시.
- **outcome lifecycle 게이팅:** `lifecycle !== "approved"`이면 `^outcome` 마커가 있어도 schema.outcomes 미생성 (toFlowSchema 규칙). 데모 sample 중 multi-gate는 review 상태로 의도적 검증 가능하게 유지.
- **SchemaGraph는 multi-gate 전용:** single-gate에서는 그래프가 정보 가치 없음. caller(`ParsedView`)가 `schema.gates.length > 1` 가드.

## 비-목표

- **graph 인터랙티브 편집** (드래그/노드 추가) — 데모는 read-only 시각화.
- **CLI analyze 출력 재현** — 별도 라운드. 현재는 SchemaBlock/MarkersBlock으로 충분.
- **markdown 편집 자동완성/syntax highlight** — plain textarea 유지. MarkerCheatsheet으로 학습 보조.
- **샘플 추가 저장/공유** — localStorage/URL 인코딩 없음. 3 sample 버튼만.
- **decision DB 연동** — 데모는 in-memory 텍스트만. `DecisionPanel`(yaml-bound)과 다른 경로.
