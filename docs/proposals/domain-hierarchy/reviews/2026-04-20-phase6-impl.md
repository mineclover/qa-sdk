### 추가/확장된 명령

1. **`qa-sdk def list --domain-root <id>`** — 파생 `domain_root`가 `<id>`와 일치하는 문서를 id 정렬 후 페이지네이션.
   - 존재하지 않는 root면 Levenshtein 유사 후보 5개 제시 + `def audit --by-domain` 안내
   - 기존 필터(`--scope` 등)와 합성 가능
   - 서버 측 필터로 표현 불가능해 클라이언트 파생 후 필터링(1회 registry 구축)
2. **`qa-sdk def context <id>` 확장** — 기존 출력 하단에 도메인 루트 한 줄 + 불일치 경고 추가.
   - 파생 root가 자기 자신이면 `도메인 루트: self`
   - `detectOwnerRootMismatch === "mismatch"` → `⚠ owner_system (X) 과 파생 root (Y) 불일치` 라인 추가
   - 파생 실패(try/catch) 시 기존 출력은 그대로 유지 (fail-open)
3. **Help text** — `DEF_HELP_SECTIONS.조회`의 `list` 라인에 `[--domain-root=<rootId>]` 시그니처 추가.

### import 추가

`deriveDomainRoot`, `detectOwnerRootMismatch`를 `definition-catalog`에서 직접 import. `buildDomainRootRegistry`는 Phase 2에서 이미 있었고 재사용.

## 사용 가이드 요약

end-user가 `domain_root`로 탐색하는 3-step 플로우:

```bash
# 1. 도메인 루트 식별 — 크기/집중도 확인
qa-sdk def audit --by-domain

# 2. 특정 도메인의 모든 문서 (id 정렬 + 페이지네이션)
qa-sdk def list --domain-root <rootId>

# 3. 개별 문서 컨텍스트 + owner-root-mismatch 경고
qa-sdk def context <docId>
```

요령:
- Phase 3 마이그레이션 전에는 상위 도메인에 귀속되지 않은 self-root 시스템이 524건 중 대다수 — `audit --by-domain`의 꼬리에 대량 1~2건 루트가 있음을 예상
- `apm-system` 같은 "정식 도메인 루트"는 링크 보완 후 등장. 현재는 해당 id를 필터로 넣으면 친절한 에러가 뜸
- `owner_system` 불일치 경고는 기계적 수정 대상이 아니라 도메인 경계 재검토 단서. `def validate`의 info 진단과 교차 확인
