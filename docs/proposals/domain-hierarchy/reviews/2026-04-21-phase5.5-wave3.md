### 공통 구조

Wave 1/2 seed 재사용:

1. **전제** — 부모 시스템이 제공하는 계약 상태
2. **동작** — 자식이 트리거하는 호출 경로

### Shell spec → integration cases 전략

viz-system-root / dkg-system-root / decode-service-spec / decision-service-spec / permission-engine-spec 5개는 2-line 또는 3-line shell 이지만, **parent 시스템이 선언한 하위 구성 요소의 조합** 으로 시나리오 도출이 가능했다. Wave 2 는 "parent-root 자체가 시나리오 대상이 되어 boilerplate 발생 위험" 을 이유로 보류했으나, 본 Wave 는 **umbrella 계약(하위 요소의 조합에서만 드러나는 속성)** 으로 접근하여 자식 재선언을 회피.

예시 — viz-system-root 시나리오 2(surface↔roleplay iframe 조합): viz-surface-system.cases.md + viz-roleplay-system.cases.md 각각이 surface/roleplay 의 단독 계약은 이미 다뤘지만, **둘의 조합에서 iframe-protocol 버전 drift** 는 root 레벨에서만 드러나는 umbrella 계약.

## 영구 defer (3건)

### 1. df-narrative-proofs (narrative)

**사유**: `knowledge_kind: narrative` + `aspect: scenario` — 서사 증명은 독자 이해용 proof cluster 이지 소비자-공급자 계약이 아님. "이 의존이 실패하면 무엇을 고치나" 가 "증명이 틀렸다" 로 귀결되어, 스펙 경로 수정이 아닌 서사 재작성이 답. `.cases.md` 의 "실패 시 수정 대상" 1줄 지침이 의미 없음.

**대안**: `packages/decision-flow/src/proof.test.ts` 의 125 tests 가 이미 proof 자체를 검증. 별도 consumer-owned cases 불필요.

### 2. motion-workspace-service (deprecated)

**사유**: frontmatter `lifecycle: deprecated` + `superseded_by: motion-workspace-system` 선언. 본문 상단 "이 문서는 motion-workspace-system 과 좌표·범위가 중복되어 Phase 5a(2026-04-20) 에서 병합되었다" 명시.

**대안**: Wave 2 가 이미 `motion-workspace.cases.md` 를 motion-workspace-system 대체재로 작성. 신규 cases 는 deprecated 문서 수명을 연장할 뿐.

### 3. platform-demo-api-spec (cross-domain, thin parent)

**사유**: 
- Wave 2 가 우려한 cycle risk: `viz-system → platform-demo-api-spec → motion-content-contract → viz-language-system` (pre-existing refines). cases.md 자체는 `refines platform-demo-api-spec` + `depends_on platform-demo-system` 만 추가하므로 **신규 cycle 은 유발하지 않음** (확인 완료).
- 하지만 부모 `platform-demo-system` 이 1-line shell(총 14줄, `^purpose` 1 문장 + frontmatter 만). 자체 계약 문구 없음 → 시나리오가 자식(platform-demo-api-spec) 의 "codec/registry/demo-snapshot 파생" 을 재선언하게 됨.
- CLAUDE.md 지침: "Don't fabricate. If no concrete failure mode exists, defer." — 시나리오의 "실패 시 수정 대상" 이 부모의 1-line 자체가 될 수밖에 없어, 해당 기준 위반.

**선결 조건**: `platform-demo-system.spec.md` 확충(통합 데모의 구성 요소, 환경 조립 계약, viz/codec 바인딩) 후 재진입.

## 발견된 이슈

### 1. Shell spec → umbrella cases 전략의 재현성

Wave 2 가 "root-shell spec 의 시나리오 도출 불가" 를 이유로 5건 보류했으나, Wave 3 는 umbrella 전략(하위 그룹의 조합에서만 드러나는 계약) 으로 4/5 를 돌파. **decode-service-spec / decision-service-spec / permission-engine-spec** 는 parent 가 풍부한 contract(api-contract / state-model / scoped-engine) 를 보유해 1-line shell 이라도 parent 기반 시나리오 작성 가능.

**권장**: 향후 shell spec 발생 시 자동 defer 가 아닌, parent 의 contract 면적 기준으로 판정. parent 가 1-line 이면 defer, 하위 구성이 3+ 요소이면 umbrella 작성 시도.

### 2. Cycle risk 해결

Wave 2 가 platform-demo-api-spec 보류 사유로 지목한 cycle risk 는 실측 결과 **신규 cycle 발생 없음** 을 확인. cases.md 는 `refines child + depends_on parent` 만 추가하므로 pre-existing refines chain(motion-content-contract → viz-language-system)과 노드가 교차하지 않음. 

그러나 **부모 shell 이 1-line** 이어서 시나리오의 품질 기준을 만족하지 못하는 것이 실제 보류 사유 — 기술적 cycle 위험이 아닌 계약 면적 부족.

### 3. Wave 1 scope-aspect 오류 7건 미수정

Wave 2 §"Wave 1 관찰된 이슈" 에서 식별된 `scope: feature/data/interface + aspect: user_scenario` 조합 오류 7건은 **이번 Wave 에서도 미수정**. 파괴적 편집 최소화를 위해 Phase 5b 또는 별도 PR 로 이관. Wave 1 12 파일 중 5건만 DB 등록.

**후속**: Phase 5b (spec/plan frontmatter aspects 작업) 과 병합 예정. 본 Wave 작업은 충돌 방지를 위해 기존 파일 수정 없이 신규 파일만 생성.

### 4. orphan 누적 증가

Wave 1(7 orphan 중 5 `.cases.md`) → Wave 2(+23 orphan) → Wave 3(+6 orphan) 누적. 정책상 `.cases.md` 는 orphan 이 정상(parent 를 `depends_on` 으로 참조하지만 자신은 참조받지 않는 leaf). 

**권장**: `def audit` 에 `*-cases` suffix 자동 orphan 면제 룰 추가 (Phase 6 CLI 확장 후보). Wave 2 §4 와 동일 제안 재확인.
