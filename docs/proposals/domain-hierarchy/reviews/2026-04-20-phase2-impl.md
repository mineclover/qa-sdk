# Phase 2 구현 보고 — validator 통합

## 구현 요약

### 변경 파일

| 파일 | 변경 |
|---|---|

### validate.ts 핵심 변경

1. **import 추가**: `deriveAllDomainRoots`, `detectOwnerRootMismatch`
2. **fail-open 파생**: `validateGraph()` 진입부에서 `deriveAllDomainRoots(registry)`를 try/catch로 감싸 실패 시 빈 Map으로 대체
3. **duplicate-coordinate 키 확장**: `tier:scope:layer:aspect` → `tier:scope:layer:aspect:domain_root`. fallback은 `entry.id` (자기 자신이 root)
4. **메시지 확장**: `중복 좌표 (...) + 도메인 루트 <rootId>: [docs...]` 형식
5. **`owner-root-mismatch` info 진단**: 각 entry에 대해 `detectOwnerRootMismatch` 호출. "mismatch"만 보고, "no-owner"는 소음이라 생략
6. **`ValidationIssue.severity` 확장**: `"error" | "warning"` → `"error" | "warning" | "info"`. `ValidationIssue.type`에 `"owner-root-mismatch"` 추가

### audit --by-domain 상태

**구현 완료**. `cmdAuditByDomain`가 `DefDataSource` → `DomainRootRegistry` 어댑터를 구축하고 `deriveAllDomainRoots`를 호출하여 domain_root별로 그룹핑 후 문서 수 내림차순으로 정렬. 각 루트마다 top 3 좌표를 출력.

## Phase 3 연결 — 우선 처리 subsystem 순위

1. **definition-* subsystem** (최우선) — 86건이 `definition-catalog-spec`으로 흡수되지만 그 안에 `decision-service-system`, `definition-harness`, `definition-quality-gates`, `definition-service-system`, `spec-*` 등 명확히 별도 시스템이 혼재. 서브루트 분리 또는 의도적 `owner_system` 재선언 필요.
2. **meta-semantic 도메인** — owner-root-mismatch 5건이 모두 `meta-semantic-system` owner인데 다른 root로 수렴. `meta-semantic-system`이 실제 도메인 루트로 등록되지 않았거나 링크가 끊겨 있음.
3. **tier-redesign / domain-hierarchy proposal** — 분할은 성공했으나 여전히 각 그룹 내부에서 17/8건 중복. `part_of` 또는 `role` 메타데이터를 좌표계로 편입하는 것이 Phase 2 제안(02-proposals-integration.md) 정석.
4. **APM 섀도우 리팩토링** (2-item 중복 `apm-codegen-system + apm-system`) — 실증 의무 대상. 링크 추가만으로 해소 가능할 것으로 예상.
5. **dkg subsystem** — `dkg-skill-catalog`, `dkg-state-store`, `dkg-system` 3-item 중복. 셋 모두 self-rooted로 남음. `dkg-system`을 도메인 루트로 통일.
