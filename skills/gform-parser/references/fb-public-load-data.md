# FB_PUBLIC_LOAD_DATA_ Reference

Google Forms `/viewform` HTML에 포함되는 `FB_PUBLIC_LOAD_DATA_`는 중첩 배열이다. 파서는 전체 배열을 의미 있는 필드 목록으로 정규화하고, 원본 배열을 애플리케이션 계약으로 복사하지 않는다.

## 핵심 위치

일반적인 질문 배열에서 다음 위치를 먼저 확인한다.

| 위치 | 의미 |
|------|------|
| `field[0]` | question ID |
| `field[1]` | 질문 제목 |
| `field[2]` | 질문 설명 |
| `field[3]` | 타입 코드 |
| `field[4]` | 응답 entry와 선택지 배열 |
| `entry[0]` | 제출용 entry ID |
| `entry[1]` | 선택지 배열 |
| `entry[2]` | 필수 여부 (`0` 또는 `1`) |

## 타입 코드

| 코드 | 의미 |
|------|------|
| `0` | 단답형 |
| `1` | 장문형 |
| `2` | 객관식 라디오 |
| `3` | 드롭다운 |
| `4` | 체크박스 |
| `5` | 선형 배율 |
| `7` | 객관식 그리드 |
| `8` | 섹션 헤더 |
| `9` | 날짜 |
| `10` | 시간 |

## 안전한 추출 순서

1. HTML에서 `FB_PUBLIC_LOAD_DATA_` 대입 표현을 찾는다.
2. JSON으로 해석하기 전에 JavaScript 표현식이 JSON과 같은지 확인한다. 외부 입력을 `eval`하지 않는다.
3. 질문 배열과 섹션 헤더를 구분한다.
4. `field[4]`가 없는 질문은 entry ID가 없는 표시용 요소로 처리한다.
5. 타입 코드와 entry ID가 실제 HTML의 `name` 속성과 일치하는지 확인한다.
6. 변경된 폼은 fixture와 생성 config를 함께 갱신한다.

질문/선택지 구조는 Google Forms DOM 변경에 취약하다. 알 수 없는 타입이나 배열 shape가 발견되면 추측해 생성하지 말고 원본 배열 일부와 함께 검토 대상으로 남긴다.
