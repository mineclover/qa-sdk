# Session: Adopt Makefile and Git Hooks for Automated Governance Enforcement

## 목적 ^purpose
`headroom` 레포지토리의 최적화된 개발 구조를 참고하여, 개발자가 아키텍처 규칙을 위반한 코드를 원격 저장소로 푸시하는 것을 물리적으로 차단하고 도구 접근성을 높입니다.

## 1. 개요 (Overview)
* 일시: 2026-06-04
* 참석자: Gemini CLI, User
* 의제: Makefile 통합 진입점 구축 및 `pre-push` Git Hook 연동

## 2. 핵심 결정사항 (Key Decisions)
* **결정 1: 통합 인터페이스(Makefile) 도입**: 복잡한 `pnpm` 스크립트들을 직관적인 `make` 명령어로 래핑하여 개발 경험(DX)을 개선함.
* **결정 2: 물리적 가드레일(Git Hooks) 적용**: `git push` 단계에서 `scripts/maintenance.sh`를 강제 실행하여, 린트 오류나 아키텍처 위반(Tier Violation)이 있는 코드가 배포되는 것을 원천 차단함.
* **결정 3: Parity 테스트 개념 도입**: In-process(메모리) 시나리오 결과와 HTTP 모드(Docker) 시나리오 결과의 정합성을 보장하는 `make test-parity` 파이프라인 개념을 수립함.

## 3. 작업 요약 (Work Summary)
* 프로젝트 루트에 `Makefile` 생성 완료.
* `make install-hooks`를 통한 `.git/hooks/pre-push` 자동 설치 로직 구현.
* 아키텍처 탐색 도구(`arch:*`)들을 `Makefile` 타겟으로 등록.

## 4. 액션 아이템 (Action Items)
- [ ] 개발팀 전파: 모든 로컬 개발 환경에서 `make install-hooks` 1회 실행 권고.
- [ ] Parity 테스트 고도화: In-process와 HTTP 모드의 스냅샷 결과(Byte-for-byte)를 직접 비교하는 테스트 러너 구현.
