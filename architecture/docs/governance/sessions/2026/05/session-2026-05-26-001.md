## Decisions

### 구조 결정

- YAML DSL을 원본(SSOT)으로 둔다.
- Mermaid는 출력 포맷으로만 사용한다.
- 구조는 폴더로, 시간은 파일명 suffix로 표현한다.
- current.md는 HEAD pointer 역할을 한다.

### 타입 분리

- BusinessLogicDocument와 MetadataDefinitionDocument를 별도 타입으로 분리한다.
- MetadataDefinitionDocument는 Business Logic Layer를 직접 정의하면 안 된다.

### Governance 위치

- Governance를 PM Tool이 아닌 아키텍처 상태 메타데이터로 취급한다.
- Governance Layer는 docs/governance/ 하위에 위치한다.

### Core System 모델링

- Core System을 Element/Relation/View로 모델링한다.
- 핵심 루프: Asset emits Event → Stage filters → Flow handles → Guard routes → Action controls → Runtime emits Event
- Runtime을 4개 Subsystem으로 분해 (EventSystem, FlowSystem, VisualControlSystem, AssetSystem)
- Editor 2종 (ae-editor, story-editor)을 모델에 포함한다.

### Scope Unit

- 모든 governance artifact에 scope 필드를 추가한다.
- 초기 Scope: SCOPE-DSL, SCOPE-VALIDATOR, SCOPE-RENDERER, SCOPE-METADATA, SCOPE-GOVERNANCE
- Compression 계층: Session → Scope → Timeline → Scope Summary → Global Summary
